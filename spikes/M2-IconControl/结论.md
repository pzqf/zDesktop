# M2 Spike 技术结论 — 原生图标坐标控制与分区背景

> 日期：2026-07-25 ｜ 对应设计案 v3.1 §四、§十一 M2
> 复现：`dotnet build -c Release && bin\Release\m2-iconcontrol.exe`
> 测试机：Windows 11 Pro for Workstations 26200 / 双显示器 / 桌面图标 31 个

## 判定：**Plan A 可行**，分区功能按 Plan A 实施

10/10 检查通过。可在**不接管图标层**的前提下读写原生桌面图标坐标，
文件路径保持不变。Plan B（文件夹门户）不启用，作为后备方案保留在设计案 §十二。

---

## 一、验证了什么

| # | 结论 | 证据 |
|---|---|---|
| 1 | 跨进程内存读写可用，**不需要管理员权限** | `OpenProcess`(VM_READ\|VM_WRITE\|VM_OPERATION) 与 `VirtualAllocEx` 对 explorer.exe 均成功 |
| 2 | 可读取图标坐标 | `LVM_GETITEMPOSITION` + 远端 POINT，31 项全部读出非零坐标 |
| 3 | 可读取图标名称 → **索引到文件的映射可建立** | `LVM_GETITEMTEXTW` + 远端 LVITEMW（x64 布局），读出「此电脑」「回收站」「Google Chrome」等 |
| 4 | 可写入图标坐标 | `LVM_SETITEMPOSITION32` + 远端 POINT，写入后回读一致 |
| 5 | 批量写入可用 | 一次写 5 项，回读 5/5 一致 |
| 6 | 全部操作可逆 | 快照 31 项坐标 → 移动 → 还原，0 项失配 |

用 `LVM_SETITEMPOSITION32`（POINT 指针版）而不是 `LVM_SETITEMPOSITION`（16 位打包版）：
多屏虚拟桌面坐标可能超出 16 位有符号范围。

---

## 二、重要发现：设计案漏了第二个前置条件

设计案 §4.2 决策 2 只把**「自动排列图标」**列为硬前置条件。实测发现还有第二个：

**「将图标与网格对齐」（`LVS_EX_SNAPTOGRID`，扩展样式 `0x00080000`）。**

它开启时，写入的坐标会被吸附到最近格点：

```
请求 (2030, 98) → 实测 (2010, 102)     偏移 (-20, +4)
```

这是最初把 spike 判成「失败」的原因——写入其实生效了，只是没落在请求的坐标上。

关键在于**它是扩展样式**，`GWL_STYLE` 里查不到，必须用 `LVM_GETEXTENDEDLISTVIEWSTYLE`
查询。本机实测 `扩展样式 = 0x14C96C30`，含 `0x80000`。

### 两种应对，推荐第二种

| 方案 | 做法 | 评价 |
|---|---|---|
| 关掉吸附 | `LVM_SETEXTENDEDLISTVIEWSTYLE` 清除 `LVS_EX_SNAPTOGRID` | 实测可行（关掉后任意坐标精确写入），但**改动用户可见的桌面设置**，属侵入 |
| **对齐到 Shell 网格** | 用 `LVM_GETITEMSPACING` 查网格间距，分区内排布按格点计算 | **推荐**。实测格点坐标可精确写入，且不改用户任何设置 |

本机实测网格间距 **76 × 100 物理像素**（随 DPI 与图标大小变化，必须运行时查询，不可硬编码）。

采用第二种意味着：**分区功能只需要「自动排列」关闭这一个前置条件**，
「与网格对齐」保持用户原样即可。这比设计案原方案侵入性更低。

## 三、分区背景合成（候选 A）开销

只测合成本身（解码 → 绘制 4 个圆角半透明矩形 → JPEG 编码 → 落盘），
未调用 `SPI_SETDESKWALLPAPER`。

| 分辨率 | 合成均耗时 | 产物 |
|---|---|---|
| 1920×1080 | 10.1 ms | 51 KB |
| 2560×1440 | 17.8 ms | 82 KB |
| 3840×2160 | 37.8 ms | 165 KB |

**判读**：4K 下 37.8ms 意味着不可能每帧重新合成。但设计案 §4.3 已规定
「拖动期间用临时交互层跟手、松手后才合成落盘」，该耗时只发生在松手那一次，
用户感知为一次性延迟而非掉帧，**可接受**。

**候选 A 通过，候选 B（DefView 之下的独立背景窗口）不启用。**

## 四、遗留待验（不阻塞 M3 启动）

1. **`SPI_SETDESKWALLPAPER` 的视觉过渡**：Windows 换壁纸有淡入动画，
   分区拖动松手后是否有可感知闪烁，需在 M3 有真实分区后判断。
2. **第三方壁纸工具共存**：必应壁纸/Windows 聚焦会覆盖我们合成的图，
   设计案 §七 已规定监听 `WM_SETTINGCHANGE` 后以新壁纸为底图重新合成，待实现。
3. **图标名称去重**：`LVM_GETITEMTEXTW` 返回的是**显示名**（隐藏扩展名时不含后缀），
   同名不同扩展的两个文件显示名相同。索引→路径的映射不能只靠显示名，
   M3 需结合 `IShellFolder` 或桌面目录枚举顺序来消歧。
4. **多显示器坐标系**：本机双屏，读到的坐标是相对 ListView 客户区的，
   跨屏分区需确认虚拟桌面坐标映射，M3 一并处理。
